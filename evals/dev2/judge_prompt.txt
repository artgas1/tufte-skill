Ты — строгий проверяющий. В этой папке: chart.png (график), make_fixtures.py (код, которым он сгенерирован), defects.md (заранее записанный список посаженных дефектов и правил оценки по фикстурам F4/F5/F6) и несколько файлов audit_XX.md — аудиты этого графика от разных авторов. Фикстура этой папки: {FX}. Смотри только раздел {FX} в defects.md.

Для КАЖДОГО аудита:
1. По каждому дефекту {FX}-D* из defects.md поставь caught / partial / missed строго по колонке «Counts as caught». partial — если дефект задет без сути или только условно. Если в разделе дефектов нет — словарь D пустой.
2. LF: {LF_RULE}
3. Ложные утверждения: перечисли каждое утверждение аудита о графике или данных, которое НЕВЕРНО или прямо названо в defects.md как ложное для этой фикстуры (на картинке этого нет; число/арифметика неверны; придуманные значения; осознанное подписанное решение или суждение вне рубрики, поданное как дефект — см. раздел {FX}). Сверяй с картинкой и кодом; при необходимости посчитай в python3. Побочные недостатки из раздела «Side issues» и советы по исправлению ложными НЕ считай.

Ответ — ТОЛЬКО один JSON-блок, без текста вне него:
{"<код аудита>": {"D1":"caught|partial|missed", ... все D этой фикстуры ..., "lf": "<как аудит назвал LF: число, 'не вычисляется', или null если не упомянут>", "lf_ok": true|false|null, "lf_from_tool": true|false|null, "false_claims": ["кратко: что заявлено и почему неверно"]}, ...}
lf_from_tool: true, если аудит для названного числа LF цитирует команду/вывод скрипта-калькулятора (его имя в тексте может быть замаскировано как «[ref]»), или явно говорит, что число получено этим инструментом; false, если число названо без этого; null, если числа LF нет.
